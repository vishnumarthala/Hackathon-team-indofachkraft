# AI scribe (ticket 038)

The session pipeline (upload -> ElevenLabs Scribe v2 -> Gemini) works for **any provider type**. From an
**in-clinic recording** it drafts a session note, suggests progress on the case's active IEP goals and, for verified
prescribers, an Rx draft that ticket 039 turns into a signed prescription. Child Development sessions keep the ISAA
extraction unchanged. Nothing is final until the provider reviews it; nothing reaches the guardian until the provider
finalizes a note **and** shares it. Not available for video (Google Meet) appointments.

## Templates (`lib/scribe/templates.ts`)

| Template (`recordings.template`) | Provider types (default on the upload form) | `recordings.kind` | Output |
|---|---|---|---|
| `child_dev_isaa` | accounts without a provider profile (legacy) | `session` | the unchanged 005/006 ISAA path (facts, score, report) |
| `therapy_session_note` | SLP, OT, ABA, special educator, physio | `session` | note: goals worked on, activities, child response, caregiver coaching, home-program suggestions, plan for next session + goal suggestions |
| `medical_consult_note` | dev-ped, child psychiatrist, paediatrician, child psychologist | `consult` | note: history, observations, assessment impressions (phrased "Clinician to confirm"), plan + goal suggestions; **Rx draft** when the uploader can prescribe |

`defaultTemplateFor(provider_type)` picks the default; the `Session type` select lets the provider choose any template.
Prompts: `prompts/session-note-therapy.md`, `prompts/session-note-medical.md`, `prompts/rx-draft.md`.

## Flow

1. `POST /api/cases/:id/sessions` `{ file_name, mime_type, size_bytes, consent?, template?, appointment_id? }` ->
   201 `{ recording_id, session_number, template, ... }`. Gates: case access (022), `session_recording` consent, and for
   scribe templates also `ai_transcription` + `ai_extraction` (020). `appointment_id` must be an appointment of the
   case's organisation and child; a video appointment -> 422 `{ error: "The AI scribe is available for in-clinic sessions only" }`;
   another org's / unknown -> 404. `uploaded_by` = the session user.
2. `POST /api/sessions/:id/transcribe` (005, now also for `consult`). DEMO_MODE picks the role-play of the template
   (`demo/fixtures/scribe-response-{therapy,consult}.json`, generated by `npm run fixtures:scribe` from
   `roleplay-{therapy,consult}-segments.json`).
3. `POST /api/sessions/:id/scribe` -> 200 `{ recording_id, session_note_id, session_note_status, goal_suggestions,
   rx_draft_id? }` (`lib/scribe/run.ts` `runScribe`):
   - claims the recording (`transcribed`/`extracted` -> `extracting`, one run at a time; 409 otherwise; 409 for ISAA
     sessions);
   - re-checks the appointment (a recording whose appointment became video -> 422, status restored);
   - context: the transcript with 024 speaker roles, the case's **active** IEP goals (active plan, active goals, latest
     value; refs `G1`, `G2`, ... in the prompt), the 021 health summary when there is a profile;
   - `assertConsentOrAbort(child, "ai_extraction")` right before **each** Gemini request (note, then Rx draft): withdrawn
     -> recording `failed` / `consent_withdrawn`, audit `consent.blocked_processing`, 422 with
     `details.reason = "consent_withdrawn"`;
   - Gemini structured output validated with Zod (`lib/scribe/schema.ts`; section keys per template); citations are
     resolved on the server (`lib/scribe/process.ts`): unknown segment ids are dropped, times come from the segment,
     `verified` = the quote is in the segment; goal suggestions need a listed goal, a value inside the goal's measure and
     an existing segment (first per goal wins); every statement is passed through the copy rule (no condition labels);
   - Rx draft only when `provider_can_prescribe(<uploader's profile>)` (028) and the template is medical; items use
     039's item shape `{ drug, strength, form, dose, frequency, duration_days, route, instructions, citations }`,
     plus `advice`, `follow_up` and the health summary at drafting time;
   - one transaction: `reports` `session_note` and `rx_draft` upserted **only while `draft`** (a final note is never
     replaced), a stale draft Rx is deleted when the uploader is no longer a prescriber, `suggested` goal suggestions
     replaced (accepted/rejected ones are kept), recording `extracted`, audit `scribe.completed` (actor `ai`).
4. Review (`/cases/:id/sessions/:recordingId`, `components/scribe/ScribeReview.tsx`), labelled
   `Suggested by DoctorNearMe - the clinician decides`:
   - **Session note**: markdown editor; citations are links `[mm:ss](#seg-<segment id>)` rendered as buttons that play
     the recording from that moment (013 `EvidencePlayer`). `PATCH /api/sessions/:id/scribe`:
     `{ content_md }` saves the draft; `{ content_md?, status: "final", visible_to_guardian? }` finalizes (default
     **not** visible) and publishes through 024 `publishVersion` (`entity_type = 'report'`) in the same transaction
     (strict audit `scribe.note_finalized`); `{ visible_to_guardian }` on a final note shares / stops sharing (new
     published version, strict audit `scribe.note_sharing_changed`). The published text has the audio links removed.
     Sharing a note that names a condition (banned stem) -> 422.
   - **Goal progress**: `PATCH /api/goal-suggestions/:id` `{ status: "accepted", value? }` (`Accept` / `Edit value`)
     records progress through 025 `recordProgress({ source: "ai_suggested_confirmed", recordingId })` (observed on the
     session date, IST) and links `progress_id`; `{ status: "rejected" }` records nothing. One decision per suggestion
     (409 after). Gate: 025 `requireIepGoalActor` + the suggestion's case; other orgs -> 404.
   - **Rx draft** card (only for viewers who can prescribe): items + `Review in prescriptions` ->
     `/cases/:id/prescriptions?from_report_id=<rx_draft id>` (ticket 039, `docs/prescriptions.md`).
5. Guardian: `/family/children/:id/notes` lists the latest published version of each finalized session note when it is
   `visible_to_guardian` (`listGuardianSessionNotes`). Drafts, suggestions and Rx drafts are never shown.
   `GET /api/sessions/:id/scribe` is provider-only (guardians 403).

## Data

- `recordings`: `kind` adds `consult`; `template` (default `child_dev_isaa`, check + kind/template consistency),
  `uploaded_by`, `appointment_id` (no FK: 030/035 own appointments and add it).
- `reports.kind` adds `session_note`, `rx_draft` (`lib/clinical/reports.ts` `inUse: true`). The 024 trigger
  `reports_publish_final` skips both kinds (session notes publish via `finalizeSessionNote`; Rx drafts never publish).
- `goal_progress_suggestions(id, recording_id, case_id, goal_id, suggested_value, evidence jsonb, rationale, status
  suggested|accepted|rejected, decided_by, decided_at, decided_value, progress_id -> goal_progress)`, unique
  `(recording_id, goal_id)`; a trigger copies `case_id` from the recording and refuses goals of another case or values
  outside the measure; RLS: care team read only.
- Privacy registry (041) `ai_scribe`: `all_ai_processing` deletes open/rejected suggestions and strips quotes and
  rationale from accepted ones (draft reports go with `case_records`); `everything` cascades with the cases. The
  guardian export already contains shared notes through `published_versions`.

## Appointments (030/035 hand-off)

`lib/scribe/appointments.ts` reads `public.appointments` defensively (`to_regclass`, rows as JSON): mode from
`service_snapshot.mode`, a `mode` column, or a `meet_url`; start from `slot` (tstzrange) or `starts_at`. Without the
table the `Appointment` select is hidden and any `appointment_id` is 404. 035 should add the FK
`recordings.appointment_id -> appointments(id)`.

## For 039 (e-prescriptions)

`reports` rows with `kind = 'rx_draft'`, `status = 'draft'`, `content` = `RxDraftContent` (`lib/scribe/schema.ts`).
Prefill `POST /api/cases/:id/prescriptions { from_report_id }` from it; re-check `provider_can_prescribe` at signing.
`rxReviewPath(caseId, reportId)` is the link the scribe uses.
